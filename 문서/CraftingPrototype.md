# 로비 장비 강화 / 옵션 제작 프로토타입

## 사용 방법

1. `02_Ingame_Lobby`에서 대장장이에게 접근하고 클릭한다.
2. 대화의 **강화**를 누른다.
3. **테스트 재료 지급**으로 재료함에 종류별 30개를 지급한다. 세이브당 1회이며 소비량이 저장된다.
4. 인벤토리의 장비를 클릭하거나 **이전/다음 장비**로 선택한다. 선택 순서는 착용 장비, 가방, 스태쉬다.
5. **이전/다음 재료**로 작업을 고르고 비용과 파괴 확률을 확인한 후 **실행**한다.

유니크는 모든 작업에서 제외된다. 제작창은 로비 대장장이에서만 열린다.

## 주문서 확정 규칙

| 시도 회차 | 파괴 확률 |
| --- | --- |
| 1~3 | 0% |
| 4 | 12% |
| 5 | 24% |
| 6 | 33% |
| 7 이후 | 80% |

확률표는 요청대로 `LobbyCraftingUI.DestructionRates`에 둔다. 이전 시도 횟수로 파괴를 판정하고, 생존했을 때 주문서 성공률을 판정한다. 실패해도 시도 횟수가 증가한다. 시도 상한은 없다.

- 무기 주문서: 기본 공격력 기준 증가.
- 방패 주문서: 기본 방어력 기준 증가.
- 성공률 / 기본 수치 대비 증가량: 60% / 10%, 30% / 20%, 10% / 60%.
- 강화량은 `scrollBonuses`에 별도로 누적한다. 기본 수치 자체는 변하지 않으므로 복리로 증가하지 않는다.
- 액세서리는 퍼센트의 기준이 될 기본 능력치가 미정이므로 주문서 정의를 아직 제공하지 않는다. 옵션 제작은 가능하다.

## 옵션 제작 임시 규칙

최대 4줄이며 제작 전용 한 줄 제한이나 접두/접미 구분은 없다. 같은 optionId는 중복 생성하지 않는다.

| 재료 | 임시 동작 |
| --- | --- |
| 재설정석 | 현재 줄 수를 유지하며 전체 재설정. 0줄 장비는 1줄 생성 |
| 부여석 | 빈 슬롯에 무작위 옵션 1줄 추가 |
| 교체석 | 무작위 옵션 1줄을 제거하고 다시 추첨. 같은 종류가 나올 수도 있음 |

모든 옵션 제작 비용은 테스트값 `1 + 주문서 성공 횟수`다. 기존 옵션을 잃을 수 있지만 장비 파괴는 없다. 주문서 수치와 시도/성공 기록은 유지한다.

## 더미 데이터 분리

`CraftingDummyData.cs`에서 주문서 정의, 재료 이름, 최초 지급량, 옵션 후보/수치, 제작 비용을 관리한다. 원본 CSV/JSON은 수정하지 않았다.

현재 재료는 장비 슬롯을 차지하지 않는 별도 **제작 재료함**이며 세이브의 `craftingStock`에 ID별 수량으로 저장한다. 아이콘/월드 드롭/루팅은 아직 연결하지 않았다. 추후 CSV 로더로 교체할 때 동일한 ID를 유지하면 재료 수량을 보존할 수 있다.

주문서 CSV 예정 필드: `itemId,equipmentType,successRate,statType,increasePercent`.

## 저장과 갱신

- 플레이어 장비, 스태쉬, 재료함을 같은 원자적 로비 저장으로 반영한다.
- 저장 실패 시 장비 변경과 재료 소비를 취소한다.
- 저장 후 화면 갱신 실패는 결과를 되돌리지 않는다. 재시도에 의한 무료 재추첨을 방지한다.
- 착용 장비 변경/파괴 시 장비 참조와 능력치를 갱신한다.
- 강화 보너스는 기존 장비 옵션과 함께 최종 능력치 계산에 반영하며 기존 정수 절삭 규칙을 따른다.

## 검증

Unity 메뉴 `Tools > Validation > Equipment Crafting` 또는 배치 실행 `-executeMethod CraftingValidation.Run`.
검증 범위: 확률 경계, 성공/실패/파괴, 비복리 강화량, 재료 소모, 4줄 제한, 유니크/잘못된 재료 거절, 옵션 중복 방지, 저장 직렬화 및 이전 세이브 호환.

실제 플레이 확인: 대장장이 진입, 장착 장비/스태쉬 선택, 파괴 시 장착 해제, 재접속 후 재료 및 결과 유지, 모바일 화면 터치.
